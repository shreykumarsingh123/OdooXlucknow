# Prepare the demo

## Steps

1. **Re-read the judging criteria and submission rules** in `docs/PROBLEM.md`. Confirm the required format and deadline.
2. **Write one story.** One user with one real problem, followed through the full workflow across roles. Do not tour the menus.
3. **Script it** in `docs/DEMO.md`, tying each step to a requirement or criterion. Open with the outcome, show the main workflow, then show one rule being enforced, such as a refused action.
4. **Make seed data believable.** Use realistic names and values, with enough records that lists and dashboards look alive, and states that cover every part of the story. Seeding must be one repeatable command.
5. **Stick to what works.** Only show features verified on freshly seeded data. Be upfront about anything incomplete rather than faking it.
6. **Prepare for failure.** Record a backup video, keep a second machine or hotspot ready, and be logged in to each role in separate browser profiles.
7. **Rehearse twice** with a timer, from a reset database. Fix only what breaks.
8. **Submit early.** Test the README from a clean clone, check repository visibility and links, then work through the submission checklist and save the confirmation.

## Output

A completed `docs/DEMO.md`, with both checklists ticked only for steps that were actually done.
